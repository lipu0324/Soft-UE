# MAC 时间、协议时间与重传

UE 1.1 §3.6.9.2.4 把 service time 定义为触发包首字节到达目的 MAC 到 ACK
首字节离开目的 MAC 的时间差。§3.6.4.2 用它从往返时间中扣除目的端处理延迟。
§3.5.13 的实现说明建议尽可能接近上网时刻启动 RTO。本实现分别表示这些时刻，
避免用 PDS 入队时间替代实际发送时间。

## 一次发送的路径

```text
PDS 生成请求 → PdsHost 待发队列 → NIC 出口队列 → 首字节发送
    附加本地发送标识                         通知 PDS，启动 RTO
```

`TransmitIdentity` 是本地元数据，不进入标准报文。它包含本地 PDC ID、起始 PSN、
PDC incarnation、包序号与尝试次数。异步通知必须匹配仍存活的同一次发送，才能更新
时间或启动定时器。因此旧尝试、重复通知、关闭后的通知，以及相同 PDC ID/PSN
重新分配后的旧通知都不会影响新连接。Probe 使用自己的 opaque 和尝试次数，
不占用数据 PSN 或数据重传槽。

`IPacketPort::provides_transmit_timing()` 为 true 时，端口承担通知义务：

- `WouldBlock` 不接受帧，不执行发送钩子；通过 writable 回调恢复，无同时间轮询。
- 已接受、仍在 NIC 队列中的帧没有运行中的 RTO，不能重复消耗重试计数。
- 首字节发送执行一次准备钩子，再通知 `Started`。
- 首字节发送前的入队失败或队列丢弃通知 `Rejected`。PDS 安排重试，但没有 RTT 样本。
- 已经上链路后随机丢包或链路中断，仍按真实发送启动 RTO，由原 PDS 恢复。

通知只加入 PdsHost 的待处理队列并唤醒后续事件，NIC 回调不递归进入 PDC。
不提供 MAC 时序的适配器保留显式的发送提交时间近似；当前实时 socket 属于这种情况。

## ACK 服务时间

PDS 保存触发 ACK 的包的首字节到达时间。ACK 在源 NIC 出队时，将差值向上量化为
128 ns 单位，写入 service time。已知但小于一个单位的时间编码为 1，因为 0 保留为
无效；超出字段范围编码为 0xffff。量化策略属于本地实现选择，测试直接检查其边界。

准备钩子只执行一次；经过后续交换机时不会再次增加 service time。写字段时保留
其余报文内容，包括 ECN、非零 UDP checksum 与 Ethernet padding；若启用 UET CRC，
只按真实 IP 长度重算受保护部分。无效报文、截短报文及未知拥塞状态类型不会被恢复
成完整有效报文。这是明文路径，TSS 需要在加密边界之前接入同一发送时刻。

源端 RTT 使用 ACK 首字节到达时间和实际请求发送时间。ACK 完整帧抵达后才处理协议，
这个后续处理时刻仍用于拥塞算法事件排序，但不增加 RTT 样本。

## 容量与验证

Fabric 的随机链路丢包发生在串行化之后：丢失帧照样占用链路带宽、出口队列和
串行化时间。出口容量不足是另一种本地入队失败。二者不能都在入口直接丢弃，
否则有损链路会表现出不存在的额外容量。

`mac_timing_test` 覆盖数据与 Probe 计时、旧通知和 ID 复用、NIC 背压、本地断链恢复、
排队帧断链丢弃，以及 100% 随机丢包的解析串行化时刻。另用一个真实 NSCC WRITE，
在目的端制造 96 μs 出口占用，检查 ACK service time 扣除该排队时间，且测得网络 RTT
保持在约 2 μs。服务字段检查覆盖 IPv4/IPv6、原生/UDP、CRC 开关共八种组合。

这些是离散事件模型的时序验证，不是硬件时间戳精度或完整 NSCC/Profile 验收。
