# PDS 保留字段与 CP 类型

UE 1.1 §3.5.10、§3.5.11.8.10 要求保留字段发送为零、接收时忽略。
`UetWireCodec` 先验证长度和启用的 CRC，再提取有效字段，重新发送时生成规范的零保留位。

已覆盖的接收字段包括 RUD/ROD 请求、ACK、NACK、CP 和 UUD 的保留标志，
原生 entropy 头末尾十六位、SYN `pdc_info` 的三个高位，以及 CP_ACK 保留字节。
ACK_CC 的保留半字节也被忽略。有效的 PSN、PDCID、MPR、重传标志及响应请求
仍参与原有状态机，忽略保留字段不会跳过 CRC 或内存授权。

CP 的 `pdc_type` 有两位实际含义（§3.5.11.8.1）：

| 值 | 含义 | 当前状态 |
|---|---|---|
| `00` | RUD | 已启用 |
| `01` | ROD | 已启用 |
| `10` | RODL | 编解码保留原值，状态机尚未启用 |
| `11` | 保留码点 | 不建立上下文 |

该字段只在 NOOP 和 Negotiation 中使用，其他 CP 忽略它。内部字段因此命名为
`pdc_type`，不能用单个布尔 `isrod` 把 `10`/`11` 错映射成已有模式。
legacy SUP1/SUE1 的单比特格式仍仅能表达 RUD/ROD，编码更宽的类型时明确拒绝。

“忽略保留位”与“接受保留码点”是不同的要求。ACK 的两位 `req=3` 是保留
码点（§3.5.11.8.6），当前在学习远端 PDCID 之前丢弃；NOOP/Negotiation 的
未启用类型也在分配 PDC 之前丢弃。两种情况计入通用接收错误计数；完整的分类
管理错误事件尚未实现，不能据此声称所有 PDS 错误处理已通过。

`pds_reserved_fields_test` 检查 IPv4/IPv6、原生/UDP、CRC 开关八种组合，验证
有效字段和规范重编码、CRC 不被绕过、CP 两位类型及 legacy 限制。实际主机路径
还验证非法 ACK 不能污染 peer binding，以及未启用 CP 类型不分配上下文。
