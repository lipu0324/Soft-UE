# NACK 分类、等待与重传

NACK 告诉 PDS 为什么包未被接受，并把相应事件交给 CMS。它不是一个统一的
“立即重发”信号。UE 1.1 §3.5.12.7 / 表 3-68 定义代码和源端动作，§3.5.21.1
定义 ROD 的 GoBackN。新逻辑继续使用原 PDC 的缓存、准入和重试计数。

## 哪些字段先决定是否处理

`NegativeAcknowledgment.hpp` 按 UE 1.1 分类全部八位代码空间。保留代码没有动作；
特别是 0x03 的旧 `UET_TRIMMED_ACK` 名称不再表示 UE 1.1 中的可执行动作。
管理器在学习对端 PDC ID 之前过滤保留代码，PDC 入口也再次校验。未知、过期或
未发送的 PSN 不得改变 CMS 记账、暂停状态或计时器。窗口 NACK 的 PSN 还必须
高于已经确认的 CACK；ROD 的 Expected_PSN payload 在使用前经过跨度/缓存检查。

通过存活尝试校验的 NACK 都调用 CMS 的事件通知接口，包括重复 NACK 和控制包 NACK。
名义在途字节则通过另一个记账接口扣除，每个实际发送尝试只扣一次。因此重复事件
可以观察，却不会反复释放同一笔拥塞窗口贡献。

## 延迟是配置，动作是协议

`Services::nack_retransmission_delays_ns` 提供四个整数纳秒槽。当前选择策略如下；
这些分组与默认时长是软件策略，不是标准新增的常数。

| 分组 | 当前默认值 | 使用场景 |
|---|---:|---|
| 0 | 0 ns | 已绑定 PDC 的 trim、窗口、ROD 缺口、未接收包、响应数据查询及接收端推断丢失。 |
| 1 | 2000000 ns | PDC/CCC/bitmap/包缓存/SES 消息或同步状态等资源不足；没有对端 PDC ID 的 NACK 也用此组暂停整个数据方向。 |
| 2 | 1000000 ns | SES 仍在处理，延迟期间 ACK 可能先到。 |
| 3 | 0 ns | 预留的本地策略槽，当前没有代码映射。 |

建连前使用 `PdsHost::configure_negative_acknowledgment_delays`，或 YAML 顶层字段：

```yaml
nack_delays_ns: [10000, 2000000, 1000000, 0]
```

四个槽都可配置为零，或配置到 8 秒。应用持有接收状态的时间、初始 RTO 和 NACK
延迟应一起选择；它们与有限重试上限共同决定何时把失败报告给应用。接口拒绝在
已有连接时更改策略。当前没有提供任意代码到分组的可编程映射。

每个 PSN 至多有一个待执行 NACK 延迟事件。重复 NACK 不重启等待、不提前消耗重试
次数。延迟事件只把请求加入原 PDS 的待准入队列，再唤醒后续进度；真正发送仍经过
对端窗口和 CMS 准入。等待 CMS、未知 PDC 的暂停和计时结束都保留同一个 NACK
原因，不会因此变成一次 RTO 指数退避。详见 [重试计时](RETRY-TIMING.md)。

## ACK 可以取消什么

如果延迟期间收到完整语义结果，取消待重传事件并正常退休该 PSN。如果只确认了
数据收到而缺少语义结果，同样取消数据重发，但保留用于恢复语义结果的 RTO。
到期后查询缓存响应，不重新读取应用缓冲区或重复计算新接收字节。

已由 NIC 接受的帧无法靠取消一个软件事件撤回；它仍可能送达，由原 PDS 的重复
消除处理。关闭 PDC 时取消所有尚未到期的 NACK 事件；事件还校验 incarnation，
不会跨越本地 PDC ID 和相同 PSN 的复用边界。

## RUD 与 ROD 的区别

RUD 重新发送对应 PSN。ROD 对 RETX 类动作采用 GoBackN，从缺失点按发送顺序
恢复后续未确认包。所有 ROD NACK 都携带 Expected_PSN（New_Start_PSN 除外），
不是只有 ROD_OOO 才解释 payload。排序使用无符号距离，支持 32 位序号回绕。
当前恢复轮次中，相同或更旧缺口的重复 NACK 不再启动 GoBackN；第一次 RETX=1
反馈或更高的 Expected_PSN 可以开启新一轮。ACK 结束当前轮次。恢复期间暂停新数据，
已确认收到的数据跳过重发，丢失语义结果由查询路径恢复。

CMS 准入与 GoBackN 的顺序也必须一致。先对已到期的恢复范围扣除旧尝试的在途贡献，
再从最早缺口发送替代尝试；不能让后面包的扣账使它先于 Expected_PSN 获准发送。
若原包 ACK 抢在替代尝试前到达，则撤销这笔未被新发送抵消的扣账，避免累计接收计数
再次释放同一批字节。这是本地重试取消的记账修正，不改变 NSCC 的窗口响应算法。
保留 §3.6.10.3 的 256 字节向上取整造成的有符号余额，不把负余额强行截成零。

PKT_NOT_RCVD/ACK_WITH_DATA 请求缓存的原始请求，不继续重复查询同一个 ACK。
完整 READ/带数据响应和安全 epoch 恢复尚未完成，因此这两类扩展的全部联合验收
仍需 M5/M6。New_Start_PSN 当前明确失败，不把收到的值直接应用到未认证的活跃
连接。PDC_ERR/PDC_FATAL 中标为 RETRY 的情形按规范允许的策略向 SES 失败；
当前不默认自动重放整个连接。这些限制阻止把本模块称为“整张 NACK 表已通过”。

## 验证与失败证据

`negative_acknowledgment_test` 检查全部代码空间、保留代码不修改状态、精确延迟、
重复 NACK、ACK 抢先到达、语义查询继续恢复、关闭/复用、不同模式和回绕；同时检查
实际重发的 PSN 顺序、RETX 轮次规则与未发送替代尝试被 ACK 取消后的字节余额。
另在实际标准报文路径注入保留 NACK，再注入来自正确对端的有效 ACK，验证保留
代码没有提前污染连接绑定。场景回归使用显式 NACK 延迟完成真实 trim 恢复。

公开 libfabric 进程测试失败时，脚本在 `build/libfabric-process-failure-*` 保留
双方完整应用输出和进程信息，并同时显示最早错误与 sanitizer 尾部。一次 8f78fba
的全套 ASan 运行出现恢复进程失败，原 stderr 尾部不足以定位根因；隔离一次及
并发退休压力下三次复查均通过。该原始失败仍保留在验证记录中，没有改记为全套通过。
